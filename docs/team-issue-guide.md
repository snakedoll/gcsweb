# 비개발자·AI용 GitHub 이슈 가이드 

기획·디자인 등 개발자가 아닌 팀원과, 그 팀원이 쓰는 AI가 GitHub 이슈로 개발팀과 일할 때 보는 안내입니다. 개발자용 전체 규칙은 `CLAUDE.md` 「작업 공유」에 있습니다.

저장소는 **공개**입니다. 이슈·댓글은 로그인 없이 누구나 읽습니다. 비밀번호, 고객 개인정보(이름·전화번호·주소·주문자 정보)는 적지 않습니다.

## 한눈에 보기

| 하고 싶은 것 | 하는 법 |
| --- | --- |
| 요청·피드백 남기기 | [새 이슈](https://github.com/snakedoll/gcsweb/issues/new/choose) → **요청·피드백** 양식 |
| 오류 알리기 | [새 이슈](https://github.com/snakedoll/gcsweb/issues/new/choose) → **오류 신고** 양식 |
| 개발자 질문에 답하기 | `확인필요` 이슈에 댓글로 답하기 (아래) |
| 나에게 넘어온 일 보기 | [나를 부른 열린 이슈](https://github.com/snakedoll/gcsweb/issues?q=is%3Aopen+mentions%3A%40me), [전달 이슈](https://github.com/snakedoll/gcsweb/issues?q=is%3Aopen+label%3A%EC%A0%84%EB%8B%AC) |
| 진행 상황 보기 | [진행 중인 작업](https://github.com/snakedoll/gcsweb/issues?q=is%3Aopen%20label%3A%EC%A7%84%ED%96%89%EC%A4%91), [답이 필요한 것](https://github.com/snakedoll/gcsweb/issues?q=is%3Aopen%20label%3A%ED%99%95%EC%9D%B8%ED%95%84%EC%9A%94) |

## 개발자 질문(`확인필요`)에 답하기

개발자가 명세·디자인에 없는 부분을 물을 때 이슈에 `확인필요` 라벨을 붙이고 댓글로 질문합니다.

1. 질문 댓글 아래에 **댓글로** 답합니다. 라벨은 건드리지 않아도 됩니다.
2. 그다음은 그 이슈 담당자가 합니다. 라벨을 떼고, 다른 역할에 알릴 결정이 있으면 늦어도 이슈를 마무리할 때까지 그 사람에게 **전달 이슈**를 따로 만들어 넘깁니다.

## 전달 이슈를 받았을 때

`전달` 라벨이 붙고 본문에 내 아이디(`@아이디`)가 있는 이슈입니다. 다른 이슈에서 정해진 결정 때문에 나에게 생긴 할 일입니다.

- 맨 위 `## 결정`에 무엇이 정해졌는지, 원래 이슈 링크가 있습니다.
- `## 할 일`에서 내 몫을 처리하고 체크합니다.
- 내 몫이 끝나면 댓글로 알려 주세요(예: `기능명세서 반영했습니다`). 이슈는 직접 닫지 않아도 됩니다. 개발 작업은 개발자의 PR이 머지되면 자동으로 닫히고, 그 밖에는 개발자가 확인하고 닫습니다.

## 직접 결정을 넘기고 싶을 때

회의나 이슈에서 정해진 내용을 다른 역할에 알려야 하면, 그 결정이 나온 이슈에 `@아이디`로 받을 사람을 부르거나 개발자에게 전달 이슈를 만들어 달라고 댓글을 남기면 됩니다.

## AI로 GitHub 이슈를 다룰 때

ChatGPT, Claude 같은 AI를 GitHub에 연결해 이슈를 쓰거나 답하게 할 수 있습니다. 이런 AI는 이 저장소의 규칙 파일을 스스로 읽지 않으므로, **이 문서를 AI에게 먼저 읽히세요.** 프로젝트 지침(또는 프로젝트 지식)에 이 파일을 넣거나, 처음에 아래 문장을 붙여 넣습니다.

```text
GitHub 저장소 snakedoll/gcsweb 의 docs/team-issue-guide.md 를 읽고, 이 저장소의 이슈를 다룰 때 그 안의 「AI가 지킬 것」을 따라 줘.
```

### AI가 지킬 것

- 이슈를 만들거나 댓글을 달기 전에 **내용을 사용자에게 보여 주고 확인받는다.** 다른 사람에게 알림이 가는 일이다.
- 새 이슈는 웹의 이슈 양식(요청·피드백, 오류 신고)으로 쓰도록 사용자에게 안내한다. 양식으로 쓰면 라벨이 자동으로 붙는다. API로 만들었으면 라벨은 붙지 않으니(저장소 협업자가 아니면 붙여도 버려진다) 본문 첫 줄에 종류(`요청` 또는 `오류`)를 적고, 라벨은 개발자가 붙인다.
- `확인필요` 질문에는 댓글로 답한다.
- 받은 전달 이슈의 내 몫이 끝나면 댓글로 알린다. 닫기는 개발자가 한다.
- 하지 않는다: 이슈 닫기, PR 머지·리뷰, 다른 사람 이슈의 담당자·라벨 변경, 코드 수정.
- 비밀번호, 토큰, 운영 DB 주소, 고객 개인정보를 쓰지 않는다. 노션·Figma 내용은 옮겨 적지 않고 링크만 붙인다.
- AI에 연결하는 GitHub 권한은 이슈 읽기·쓰기만 준다(코드 쓰기 권한은 주지 않는다).

## 라벨 뜻

| 라벨 | 뜻 |
| --- | --- |
| `요청` `오류` `작업` `전달` | 이슈 종류 (요청·피드백 / 오류 신고 / 개발 작업 / 이슈에서 결정된 전달사항) |
| `프론트` `백엔드` `디자인` `기획` | 관련 파트 |
| `진행중` | 담당자가 작업 중 |
| `확인필요` | 기획·디자인 등의 답을 기다림 |
